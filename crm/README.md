# Локальный учёт игр, приставок и аксессуаров

Это однопользовательский локальный веб-MVP для учёта закупленных и проданных игр, игровых приставок и аксессуаров. Приложение заменяет Excel в базовом сценарии: создать закупку, добавить физические товары, проверить диски, видеть остатки, отметить продажу и посчитать прибыль.

Apify API из веб-MVP не вызывается. Рыночные данные импортируются только из локальных JSON-файлов.

## Быстрый запуск Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m app.cli init-db
python -m app.cli seed
python -m app.cli import-market "data/import/*.json"
uvicorn app.main:app --reload
```

Открыть:

```text
http://127.0.0.1:8000
```

## API для ADB-бота Авито

Чтобы бот с другого устройства или ПК в той же Wi-Fi сети мог отправлять объявления в CRM, запускайте сервер так:

```powershell
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

URL для бота на этом ноутбуке:

```text
http://127.0.0.1:8001/api/market/imports/avito
```

Если в `.env` задан `MARKET_IMPORT_TOKEN`, бот должен отправлять заголовок:

```text
Authorization: Bearer <MARKET_IMPORT_TOKEN>
```

Если порт 8000 занят, запустите:

```powershell
uvicorn app.main:app --reload --port 8001
```

## Где данные

База задаётся через `DATABASE_URL` из `.env`. По умолчанию это SQLite:

```text
data/avito_scraper.db
```

Резервная копия:

```powershell
Copy-Item data\avito_scraper.db data\backup_avito_scraper_$(Get-Date -Format yyyyMMdd_HHmmss).db
```

PostgreSQL тоже поддерживается:

```text
DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/crm_inventory
```

Перенос текущей SQLite-базы в Postgres:

```powershell
python -m app.cli migrate-to-postgres --source sqlite:///data/avito_scraper.db --target postgresql+psycopg://postgres:postgres@localhost:5432/crm_inventory --replace
```

Техническая дедупликация:

```powershell
python -m app.cli dedupe
```

Она сливает дубли категорий, каталога, aliases, импортной аналитики и лишние сопоставления рынка. Одинаковые физические товары в остатке не удаляются, потому что это могут быть реальные несколько дисков.

## Структура

- `app/main.py` — FastAPI web-приложение.
- `app/models.py` — SQLAlchemy 2 модели.
- `app/inventory.py` — seed, закупки, товары, продажи, экспорт.
- `app/market.py` — импорт локальных JSON, дедупликация, сопоставление и медиана.
- `templates/` — Jinja2 страницы.
- `static/` — CSS и небольшой vanilla JS.
- `data/import/` — локальные JSON для импорта.
- `data/exports/` — CSV/zip-экспорты.

## Работа в интерфейсе

### Добавить закупку

Откройте `Новая закупка`, заполните дату, источник, статус, общую стоимость, доставку и расходы. Ниже добавьте строки товаров. Если `Количество` больше 1, приложение создаст отдельный физический экземпляр для каждой единицы.

### Добавить большой лот

В `Новая закупка` используйте блок быстрого режима: вставьте названия игр по одному на строку, выберите общую платформу и локализацию. Себестоимость распределяется как:

```text
(общая стоимость + доставка + прочие расходы) / количество товаров
```

Поле называется `Расчётная себестоимость`; его можно изменить вручную у каждого товара.

### Продать товар

В разделе `Товары` нажмите `Продать`, укажите цену и дату. Статус станет `Продан`, прибыль считается как:

```text
цена продажи - расчётная себестоимость
```

Если себестоимость не указана, прибыль показывается как неизвестная.

### Каталог и категории

В `Каталог` можно добавить новую игру, до двух альтернативных названий и объединить ошибочные позиции. В `Категории` можно добавлять подкатегории любой вложенности. Системные категории удалить нельзя.

## Рыночные данные

Импорт:

```powershell
python -m app.cli import-market "data/import/*.json"
```

Импорт:

- принимает один или несколько JSON-файлов;
- проверяет массив на верхнем уровне;
- дедуплицирует по `id`;
- сохраняет полный `raw_json`;
- обновляет существующее объявление при повторном импорте;
- не создаёт товары инвентаря;
- не создаёт каталожную позицию для каждого заголовка.

Сопоставление использует основное название и aliases без ML/LLM. Цифровые товары, подписки, комплекты и неоднозначные строки не участвуют в оценке физических дисков.

Рыночная оценка показывает медиану, минимум, максимум, количество объявлений и уверенность. Сначала используются частные продавцы; если их меньше трёх, берутся все подходящие физические объявления.
